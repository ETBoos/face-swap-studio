# 实时出站验收量表（测试前锁定）

> 基线：修阿最终需求 = Win 物理摄像头 → 照片/`.dfm` 两模式 → 微信 PC 出站 → 手机实时接听。  
> **离线成片 / 仅本地预览窗样片不得代替本表。**  
> 状态栏：未实现 | 已写代码 | 自动测试通过 | 真机通过

## 0. 闸门定义（产品 + 技术共用）

| 闸 | 通过条件 | 未通过不得宣称 |
|----|----------|----------------|
| G1 出站设备 | 微信 PC（或 WhatsApp Desktop）设置里能选中目标摄像头设备名，且预览非黑屏 | 「已支持微信/WhatsApp」 |
| G2 实时换脸 | 摄像头实时源；对方手机录屏可见换脸；过下方像真度分 | 「可用成品 / 顶级真实」 |
| G3 稳定 | 连续通话 ≥30 min 无崩溃；断线可重连说明 | 「稳定商用」 |

## 1. 测试顺序（强制）

1. **测试画面出站**：纯色/走动秒表全屏 → L1 或 L3 → 微信 → 手机录屏（证明出站链路，不接换脸）
2. **即用模式（Deep-Live-Cam）**：照片脸。先验静帧首帧进预览窗，再验 DLC Live 窗口 + 物理摄像头
3. **顶级模式**：`.dfm` + 物理摄像头实时
4. 每模式交：**本机预览录屏 + 手机接收端录屏**

## 2. 必须记录的环境指纹

- Windows 版本 build
- GPU 型号 + 驱动版本
- OBS 版本
- 虚拟摄像头实现与版本（L1：DroidCam Virtual Output **插件+驱动**；勿装成手机输入插件）
- 微信 PC / WhatsApp Desktop **精确版本号**
- 出站设备在系统中的**真实设备名**
- Deep-Live-Cam / DeepFaceLive 构建 ID（commit）、模型文件名、sha256（见 `ENGINE_VERSION_PIN.md`）
- 采集卡型号（若 L3）+ USB 口位置（后置直连）
