# 专业人物模型：在自己的界面中预览和输出

从 0.2.0a2 开始，专业人物模型模式直接在 FaceSwap Studio 内显示加载状态、摄像头换脸预览和输出状态，不再启动 DeepFaceLive 的图形界面或要求用户手动配置其节点。

## Windows 使用步骤

1. 关闭旧版 FaceSwap Studio，安装新版主程序。已有项目和激活信息保留。
2. 将完整的 DeepFaceLive **NVIDIA** 便携引擎解压到固定目录，例如 `C:\DeepFaceLive_NVIDIA`。这是运行依赖，无需打开它的 `.bat` 或界面。主程序安装包仍不包含该环境和模型权重。
3. 在 FaceSwap Studio 的「画面与引擎设置」中，将「专用模型引擎目录（NVIDIA）」指向该目录。其下应有 `_internal\python\python.exe`、`_internal\DeepFaceLive\main.py` 和完整的 `modelhub`、`xlib`、CUDA 运行库。照片模式使用的 FaceFusion 环境不能代替此环境。
4. GPU 保持 `cuda:0`（第一张 NVIDIA 显卡），建议预览 1280×720。首次加载慢时把「首帧等待上限」设为 180 秒。
5. 激活含专业模型权限的 Pro / Studio 授权，选择「专业人物模型」，选中已经导出的 `.dfm`，选择真实输入摄像头并确认素材授权。
6. 点击「开始预览」。软件依次显示检查环境、加载检测器、面部定位器、人物模型、预热、打开摄像头等状态；收到真实处理帧后显示预览。
7. 检查脸部、嘴型与侧脸，再点击「开始输出」。需要时安装随包的 FaceSwap Studio Camera 组件，并在通话或直播软件中选择该设备。

不会自动启动输出。检测不到单个人脸、模型输出无效、画面过期或引擎异常时，输出暂停；恢复后需要手动再次开始输出。Pro 授权到期会停止专用模型预览和输出。

## 兼容范围

- 目前使用官方 DeepFaceLive 接口，参考版本提交 `fc7b787bda2b8c186e142c52857458eea3a935ed`。
- 需要 NVIDIA / CUDA 构建；DX12 / DirectML 构建不在本版支持范围。
- DFM 输入是 `in_face:0`，可带 `morph_value:0`，输出为 DeepFaceLive 约定的人脸和两个蒙版。支持正方形 64–640 模型输入；当前采用默认 whole-face 对齐（coverage 2.2）。任意 ONNX 文件改后缀不会变成兼容 DFM。
- 已有 `.dfm` 直接读取，不复制到 userdata，也不修改或删除原文件。
- GPU 实际会话必须启用 CUDA；加载失败不会悄悄换成 CPU。检测器和定位器使用引擎目录中已有的模型，不主动下载。
- 主程序最高接收 1920×1080；这不是画质或帧率承诺。小模型输入放大到大画面不会自动增加真实细节。
- 本版仍是预览版，尚未完成用户 RTX 4080 SUPER 的长时间 GPU、真实人物 DFM 和各通话平台验收。自动测试中的合成 DFM 不代表真人效果。

## 授权与分发边界

激活码控制 FaceSwap Studio 的功能入口与输出权限，也检查运行中的授权失效。它不限制用户独立使用开源 DeepFaceLive，不能锁住已交给用户的明文 DFM。此改动没有实现模型加密或保证无法破解。

DeepFaceLive 使用 GPL-3.0。保留 `THIRD-PARTY-NOTICES/deepfacelive` 中的许可证、来源和本版 worker 源码；独立进程不自动意味着整个集成可闭源。正式商业发行前按实际分发方式确认对应源码和许可证义务。模型权重的许可需单独确认。

## 排查

- 找不到引擎：选择解压根目录，不要选 `.exe`、压缩包或 `_internal` 子目录。
- 缺少检测器/定位器：完整解压 NVIDIA 运行包，不要只复制 `main.py`。
- CUDA 初始化失败：确认便携包自带 CUDA/cuDNN 完整、驱动可用；不要把 FaceFusion Conda 的 DLL 混到便携引擎中。
- 没有人脸或多张人脸：检查输入摄像头是否误选虚拟摄像头，确保画面仅一人、光线足够。
- 模型不兼容：从训练项目导出 DeepFaceLive 支持的 DFM；不是训练 checkpoint 或压缩包。
- 日志入口仍是主界面「打开诊断日志文件夹」。
