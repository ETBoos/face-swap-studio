# 产品方向与交付标准

更新：2026-09-16。适用于接管后的 0.2 系列；替代旧文档的剧组限定与质量分级宣传。

## 产品定位

服务有实时换脸视频通话、直播需求的桌面用户。用自己的或已获许可的素材，以少量操作得到稳定、自然的实时画面。技术真实感、动态效果、新手成功率和软件体验是主要竞争力。

照片与专属模型是输入方式；哪个更好，要在相同设备、输入、分辨率与延迟条件下比较。不能把引擎名称或模型格式直接当作真实感等级。

## 当前交付边界

0.2.0a1交付可安装应用、独立虚拟摄像头组件、真实照片处理适配代码及故障恢复。FaceFusion环境和模型仍需单独准备，是下一轮降低新手门槛的首要缺口。DeepFaceLive暂保留外部启动；真实模型速度、画质、具体通话兼容性没有实测数据。自动测试不能代替这些结果。

## 工作顺序

1. **可安装闭环**：主程序/组件安装、启动、卸载；设置重启保留；新手流程明确；不输出演示或原始摄像头；错误可重试。每个构建提供SHA256、版本和来源提交。
2. **引擎准备体验**：可商用模型路线确认后，提供受校验的依赖准备、下载/安装进度、断点恢复和失败修复。不要让新手手填Python、CUDA或模型代号。
3. **真实模型基线**：锁定版本、模型哈希、显卡/驱动、输入分辨率及接收端版本；录制相同动作样本并记录独立处理帧率、p50/p95延迟、显存和掉帧。
4. **动态质量**：优先修嘴唇牙齿、侧脸、遮挡、肤色边缘、连续帧抖动。每项保留相同条件的前后对比，不能只挑静态截图。
5. **兼容和稳定**：从一个通话场景与一个直播场景完成双端验收；短测后逐步推进30分钟、2小时、8小时持续运行；检查拔插、休眠、设备抢占、引擎崩溃与重连。
6. **定价和商业验证**：基本付费版本应满足真实通话/直播用途。先衡量首次成功出画、接收端成功、七日复用、付费转化、退款和每用户支持时间，再决定最终套餐。暂不扩充复杂座位数或硬件捆绑。

## 第一阶段的产品指标

以下是待验证的目标，不能对外当已实现性能：

- 下载和依赖准备完成后，10名初次使用者至少8名在5分钟内完成接收端出画。
- 在明确的主流基准设备上优先稳定720p30，再决定1080p档位；分别报告处理帧率与输出重复帧率。
- 本地新增延迟与网络通话延迟分开测量；报告p95，保留测量方法和原始记录。
- 连续说话、左右转头、眨眼、手遮嘴、眼镜反光、暗光等固定脚本分别评分，禁止用平均分掩盖单个严重故障。
- 软件启动不得开启摄像头或输出；开始、暂停和失败状态一致；用户手动暂停后必须手动恢复。
- 包内无自动上传照片/摄像头画面；诊断信息本地保存，用户自行决定是否分享。

## 竞争力判断

虚拟摄像头、双引擎、安装包已是市场基础能力。可积累的优势是：可复现的质量评测集、长期稳定性、常见错误的自动修复、可靠硬件配置档，以及新用户的首次成功率。营销内容必须来自真实接收端与固定测试动作，价格围绕完整用途与服务价值验证。

商业版本发布前还需完成模型许可、签名安装包、真实授权服务和售后流程。当前阶段按Alpha体验版管理，优先缩小真实产品与承诺之间的差距。
