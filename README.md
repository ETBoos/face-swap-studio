# FaceSwap Studio

面向有实时换脸视频通话、直播需求的桌面用户。重点是动态真实感、稳定输出、第一次使用也能理解的操作流程。

当前版本：**0.2.0a1，Windows 可安装预览版**。本版正在建立真实输入、换脸、预览、输出和故障恢复的完整链路。模型效果、GPU 性能和具体通话平台的兼容性仍需真机验收；此版本不代表已达到正式商用交付标准。

## 安装与首次使用

从本仓库 **Actions → Windows package → 成功运行的 Artifacts** 取得构建产物：

- `FaceSwapStudio-0.2.0a1-windows-x64-setup.exe`：主程序，按当前用户安装，无需自行安装 Python。
- `FaceSwapStudio-0.2.0a1-windows-x64-portable.zip`：便携版，完整解压后运行。
- `FaceSwapStudio-Camera-Setup.exe`：独立虚拟摄像头组件，安装时需要 Windows 管理员权限。主程序开始菜单也提供该组件的安装入口。
- `安装配置教学.md`：随主程序安装，并在开始菜单提供入口，包含 FaceFusion、授权、虚拟摄像头和 OBS 配置步骤。
- `SHA256SUMS.txt` / `build-info.json`：文件校验与构建信息。

按主界面四步操作：

1. 查找并选择摄像头。查找设备不会打开摄像头。
2. 选择照片。照片模式无需先创建项目；专属 `.dfm` 模式仍通过 DeepFaceLive 外部窗口运行。
3. 开始预览，确认本机换脸画面。初次使用还需要准备兼容的 FaceFusion 3.9.0 环境与模型，在「画面与引擎设置」选中其目录和 Python。安装包**不含模型权重或 FaceFusion 运行环境**。
4. 安装摄像头组件后点击开始输出，在目标软件中选择 **FaceSwap Studio Camera**，确认接收端画面和声音。输出设备启动成功不等于目标平台已经通过兼容性验收。

没有引擎和模型时，可选择明确标注的「摄像头演示」体验操作；演示不会换脸，也不能开始输出。真实引擎缺少依赖、模型校验失败、摄像头断开等情况会显示具体原因。

目前的安装包未配置代码签名证书。Windows 可能显示未识别发布者；本仓库不提供关闭系统保护的操作步骤。

## 本版已实现的代码

| 模块 | 实现范围 | 验证边界 |
| --- | --- | --- |
| 中文桌面流程 | 选设备、照片/模型、预览、输出；保存设置；项目可选 | Qt 流程测试、界面截图、冻结程序启动检查 |
| FaceFusion 照片适配 | 官方 3.9.0 API 的独立 Python 工作进程；本地模型检查；摄像头采集与处理帧回传 | 合成依赖的跨进程测试；尚未取得真实模型/GPU 效果数据 |
| 虚拟摄像头输出 | 独立发布线程、最新帧缓冲、原生 DirectShow 组件；停止或异常显示占位画面 | Windows 流水线检查组件安装、像素传输与卸载；具体通话软件待测 |
| DeepFaceLive 专属模型 | 检查环境、暂存 `.dfm`、启动外部窗口、监控退出 | 尚未接收其视频帧；不能在本程序中预览或输出 |
| 密钥激活 | Ed25519 签名凭证、设备额度、在线激活与刷新、离线授权导入、Railway 后台 | 支付与订单系统尚未接入；发卡由受管理员令牌保护的接口完成 |

检测不到单个有效人脸、引擎中断或收到演示帧时，输出会暂停，不自动切回原始摄像头。照片模式当前支持到 1920×1080，默认 1280×720；分辨率选项不是帧率或画质承诺。

## 开发

```sh
uv sync --extra dev
uv run pytest -q
uv run python -m face_swap_studio
```

无摄像头的界面启动检查：

```sh
FSS_SMOKE=1 FSS_OFFSCREEN=1 uv run python -m face_swap_studio --offscreen
```

设置和项目默认保存在用户目录 `~/FaceSwapStudio`；测试可用 `FSS_DATA_DIR` 指定隔离目录。卸载主程序保留个人数据，摄像头组件有独立卸载入口。

## 第三方组件

原生虚拟摄像头基于 MIT 许可的 UnityCapture，保留来源与许可说明，并使用独立设备标识。PySide6 等依赖的许可证随构建包提供。模型权重的使用和分发条件与应用代码独立，本包不附带模型权重。
